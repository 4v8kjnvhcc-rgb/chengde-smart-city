数据资源采集汇聚系统
1.数据资源采集汇聚系统—指标与目录体系构建、数据融合治理平台—数据目录管理系统、部门数据共享门户用同一套表，新增一个字段来区分该目录是来自指标与目录体系构建还是来自数据目录管理系统，新增一个状态来区分目录状态，审核通过后的目录在部门数据共享门户展示；
2.所涉及的数据字典均放在系统字典表sys_dict,sys_dict_item;
3.将以下两个系统的功能合并成一个系统的，功能最全。
数据融合治理平台—数据目录管理系统和数据资源采集汇聚系统—指标与目录体系构建复制资源编目和目录发布，部门数据共享门户负责目录申请，数据融合治理平台—数据目录管理系统的资源目录门户负责部门数据共享门户申请的资源的订阅、审批、分发等。

编目 → 分类（含涉密性）→ 注册发布 → 审批（唯一性/完整性/关联性/表述性校验）→ 门户发布 → 部门数据共享门户申请 → 资源目录门户订阅登记→审批→分发（库表自动同步 / 接口封装转发+token / 文件FTP）→ 数据变更按订阅更新。

关键边界说明
部门数据共享门户独立存在、只负责"目录申请"（需求方检索+申请），不并入本系统；
本系统"资源目录门户"负责部门门户所申请资源的订阅、审批、分发，二者通过目录驱动交换形成闭环。

数据资源采集汇聚系统—指标与目录体系构建具体要求：
按照数据资源目录编制标准，对接入汇聚的数据资源进行本地化编目，形成地方数据资源目录为本地区业务提供数据服务。目录编制服务提供对资源目录进行新增，或对已发布的资源目录删除、更改等功能。资源目录管理对注册的资源进行标准化或者按照用户自定义的方式进行分类管理，并对资源的编目、注册与审核进行权限的分配与管理。
1.1.1.1.2.3.1数据资源编目管理
支持符合行业标准的管理元数据范围，包括信息资源分类、信息资源名称、信息资源代码、信息资源提供方、信息资源格式等核心元数据，以及共享属性、更新周期等扩展元数据，统一编目为资源并开放到资源服务平台门户供资源需求方调阅申请。
（1）批量新增数据资源
支持批量编制数据资源，从已有不同数据库表中抽取核心元数据，生成标准数据资源目录。
（2）手动新增数据资源
支持手工编目数据资源，支持将库表、文件等数据挂载到对应资源目录，实现资源与真实数据无缝融合。
（3）查看数据资源
支持查看编目好的数据资源，预览资源详细信息。
（4）查询数据资源
支持查询编目好的数据资源，通过审核状态、共享方式以及数据资源名称组合查询。
（5）删除数据资源
支持删除编目好的数据资源。
（6）编辑数据资源
支持编辑编目好的数据资源。
（7）批量导入数据资源
支持通过电子表格方式批量导入线下整理编制好的数据资源。提供多种导入校验规则。
（8）批量导出数据资源
支持通过电子表格方式批量导出编制好的数据资源。
1.1.1.1.2.3.2数据资源分类
资源分类支持符合国家标准的信息资源目录要求的资源目录多级分类管理，提供按类、项、目、细目的分类规范进行资源编目，包括基础资源目录、部门资源目录、主题资源目录类等；支持资源分类涉密性管理，支持根据业务需求从初始目录编目即按涉密性进行控制，非涉密资源目录默认开放到门户统一展现，涉密资源目录需授权给需求方才可见，从源头保证信息资源安全性，灵活掌控目录可见性。
资源分类支持对目录的增、删、改、查，支持对目录进行关联资源和解除资源操作。
（1）新增资源分类
支持新增资源分类，其中资源目录名称、所属资源目录、分类代码、是否涉密为必填项。
（2）编辑资源分类
用户可对已有目录进行编辑修改，资源目录名称、所属资源目录、分类代码、是否涉密和描述均可修改。
（3）删除资源分类
支持删除目录，目录下关联的资源即刻解除关联，该资源可被其他目录再次关联。
（4）查询资源分类
支持按资源分类名称模糊查询目录。
1.1.1.1.2.3.3资源目录注册发布
（1）资源分类关联资源
用户可在目录下关联资源，只有未被关联的资源才可以进行关联资源操作。支持批量解除已关联的资源。提供单个资源、批量资源同资源分类解除注册关系。
（2）数据资源编目注册发布
支持数据共享平台资源目录注册，通过将资源分类与数据资源编目进行关联注册形成标准的数据资源目录，满足机构间的数据交换共享需要。
（3）资源目录注册发布
1）资源分类关联资源
用户可在目录下关联资源，未被关联的资源才可以进行关联资源操作。
2）关联资源解除
支持批量解除已关联的资源。提供单个资源、批量资源同资源分类解除注册关系。
1.1.1.1.2.3.4数据资源目录审批
资源服务平台资源目录审核，对数据唯一性、完整性、关联性、表述性进行校验，确保信息资源的准确和有效。审核内容包括资源分类中的目录新增、编辑、删除和资源的关联、解除关联；资源编目中的新增、删除、发布、下线操作都需要进行审批。
支持批量审批和单个审批，可选择审批通过或拒绝。若选择审批拒绝则需要填写审批意见。

4.概念理解：
关系拆解
-1. 数据资源 与 数据分类 —— 互相对应，但不互相包含

每个数据资源在核心元数据里就带"信息资源分类"字段（如"人口主题"），这个字段值必须与数据分类体系中的某个节点一致。所以分类既是独立框架，也体现在资源属性上。
数据分类本身只是"文件夹树"，不含任何数据；数据资源本身也是独立实体，不依赖分类存在。
-2. 数据目录 —— 依赖前两者，是两者"关联注册"的产物

文档原文："将资源分类与数据资源编目进行关联注册形成标准的数据资源目录"。
操作约束："只有未被关联的资源才可进行关联资源操作"——说明一个资源挂到分类节点下、注册发布，才成为目录的一项。
因此：数据目录不能脱离数据资源（无资源可挂）和数据分类（无归类框架）而独立存在；而数据资源、数据分类可各自独立存在。
-3. 系统中的层级包含关系

数据分类（树） ⊃ 数据目录（某分类节点下的标准目录） ⊃ 数据资源（目录中挂载的具体资源）

流程位置（谁先谁后）
编目产生数据资源 → 建立数据分类框架 → 把资源关联到分类节点并注册发布 → 形成数据目录 → 审批 → 门户发布 → 部门门户申请 → 订阅/审批/分发。

实例（以"人口基本信息"为例）
数据资源：公安局的"人口基本信息"库表，编目后带元数据（分类=人口主题、提供方=公安局、格式=库表、共享属性=有条件共享）。
数据分类：挂到"主题资源目录 / 人口主题"节点（类=主题，项=人口主题）。
数据目录：将该资源关联到"人口主题"节点 → 注册发布 → 形成标准数据目录项"人口基本信息"。
审批通过后门户发布 → 卫健委在部门数据共享门户检索并申请 → 资源目录门户完成订阅、审批、分发（库表自动同步）。
简言之：资源是"米"、分类是"米缸的格子"、目录是"贴好标签、能端出去共享的那一格米"。
