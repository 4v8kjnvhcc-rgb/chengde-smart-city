## 结论摘要

1. **保留现网**：`/analytics/population` 五区 Hub（M152～M174），深链归集 / 治理 / 资源中心 / 目录；不新建独立人口子系统。
2. **五区内关系**：采集进 → 治理净 → 核心存 → 分流到内部严 / 共享出；治理问题反馈采集侧闭环；禁止旁路核心。
3. **与外部系统**：采集↔归集；治理反馈↔数据治理；核心↔数据融合；元数据横切五区（共享区目录最显式）。Hub 做设计/挂载/消费，ETL 跑在归集·治理·融合。
4. **展示**：取消 DataEase；不用 BI；十四模型自研台账 + 指标 + 样例/结果表（Hub 已落地：模型抽屉加载样例表；后端拒绝人口 embed）。
5. **ETL 中间件**：与三模块一致 — Kettle 执行 + DolphinScheduler 定时；人口域不自建 Spring 扫表。
6. **范围**：规格 A 已完成；B 已开工（去 embed / 自研样例）；主题表真源、校核引擎、生产接口属后续 B 余项 / C。未提交 git。
