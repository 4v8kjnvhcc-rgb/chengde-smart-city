## 怎么用这份手册

- **第一次上线** → 看 **A. 初次部署**（从装 Docker 到跑通，按顺序做完）。
- **以后改了代码/配置再发版** → 看 **B. 后续更新部署**：**先 B0 备份**，再按改动做 B1/B2/B3；失败则 **B5 回退**。
- 机器信息、端口、运维、排障在 **C. 附录**。

**方案要点：**

1. 仅 **Docker + Compose** 用离线包装（麒麟 yum 装不好）；**Redis / OM / DS / Kettle / 门户**跑容器；**业务与分层 MySQL 在独立库机**（不要求再把业务库放在 .51）。
2. 服务器架构为 `aarch64`：Docker/Compose 安装包须用 **aarch64** 包（见 A2，勿下 x86_64）。
3. 现场 Docker **能出网**：中间件镜像在 .51 直接 `docker pull`（会拉 arm64 变体）；门户前后端镜像由**本机**按 `linux/arm64` 打好后 `docker load` 到 .55（现场不 build）。
4. 代码 + 配置（含 `prod-*.env`）由**本机打包**离线投递，服务器不依赖 `git`。
5. ESB 外挂 **10.10.10.61:7000**，不在本方案内。
6. **分层库连接（方案 B）**：`compose/prod-app.env` 中 `MYSQL_`* → 控制面；`LAYER_ODS_*` / `LAYER_DWD_*` → S6；`LAYER_DWS_*` / `LAYER_ADS_*` → S7。未配 `LAYER_*` 时回落 `KETTLE_TARGET_*`（同机方案 A）。
7. **存储生命周期（备份/归档/销毁）**：备份库 `{源库}_bak` **由现场在对应 MySQL 手工创建**（见 [C6](#c6-存储生命周期备份归档销毁)）；归档 gzip 落应用机宿主机 `/data/smart-city/archives`，目录须给容器用户 **uid 10001 写权限**。

# A. 初次部署

一次性走完下面 6 步即可上线。

```text
本机打包            →  A1  产出：代码包 + 应用镜像
两机装 Docker       →  A2  .51 / .55 各装一遍
投递代码 + 防火墙   →  A3（含库机 13306 放行说明）
.51 起中间件        →  A4  Redis；需要时 --all
确认库机 + .55 起门户 →  A5（prod-app.env 方案 B）
验收                →  A6
```

## A1. 本机打包（办公电脑，可出网）

> 生产密码文件 `compose/prod-mid.env` / `prod-app.env` 仓库里**已有**，打包脚本会自动带上，现场不用改。要换新密码：`.\scripts\gen_prod_env.ps1 -Force`。  
> **统一输出目录：** 仓库根下 `release/`（脚本自动创建；已 gitignore，不会进 git）。代码包与应用镜像都放这里。  
> **本机注意：** `scripts/*.ps1` 须为 **UTF-8 BOM**（Windows PowerShell 5.1）；打出的 `prod-*.env` 与 `.sh` 须为 **Unix LF**（脚本已自动规范化）。Docker Desktop 未启动时，双击 `build_prod_images.bat` 会尝试自动拉起。

**① 打代码包**（先把要上线的改动 **push 到远程**，打包读的是 `origin/<分支>`，不是本机工作区）：

双击 `scripts\pack_prod_release.bat` → 输入远程分支名。
或命令行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\pack_prod_release.ps1 -Branch feature_yxj
```

脚本会先 `git fetch origin <分支>`，再按远程提交打 `release/chengde-smart-city_<分支>_<sha>_<时间>.tar.gz`（仅 `compose/` + `scripts/prod_up_*` + 本机 `prod-*.env`；**不含** docs / catalog / 前后端源码）。

**② 打应用镜像**（本机需已启动 Docker Desktop；同样先 fetch 远程分支）：

双击 `scripts\build_prod_images.bat` → 输入远程分支名。

脚本会按 `linux/arm64` 打包（与现场 `aarch64` 一致）。产出到 `release/`：`chengde-app-images_<分支>_<sha>_<时间>.tar`（前后端镜像 `smart-city/platform-*:local`）。

> 本机若是 Windows/x86，需 Docker Desktop 支持跨架构构建（默认可用）；首次可能较慢。**不要**用未指定平台打出的 amd64 镜像上到 aarch64 机。

从 `release/` 把这两个文件拷到 U 盘 / 通过内网传到服务器（建议至少保留最近 2～3 次，方便回退）。

## A2. 两台机装 Docker + Compose（离线）

**.51 和 .55 都要做一遍。** 安装包架构为 `aarch64`（与 `uname -m` 一致）。

**① 检查环境：**

```bash
cat /etc/os-release    # V10 (Lance)
uname -m               # 须为 aarch64（ARM64；勿用 x86_64 安装包）
yum remove -y podman docker-runc 2>/dev/null || true
```

**② 下载两个安装包**（aarch64），放到本机或能上网的机器下载后，上传到服务器 `/opt/docker-install/`：


| 文件                             | 说明                                                   | 下载地址                                                                                                                                                                                 |
| ------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `docker-24.0.9.tgz`            | Docker 引擎静态包（**aarch64**）                            | [https://download.docker.com/linux/static/stable/aarch64/docker-24.0.9.tgz](https://download.docker.com/linux/static/stable/aarch64/docker-24.0.9.tgz)                               |
| `docker-compose-linux-aarch64` | Compose 插件（**aarch64**；勿选 x86_64 / darwin / windows） | [https://github.com/docker/compose/releases/download/v2.29.7/docker-compose-linux-aarch64](https://github.com/docker/compose/releases/download/v2.29.7/docker-compose-linux-aarch64) |


目录索引（可换版本时对照）：引擎 [https://download.docker.com/linux/static/stable/aarch64/](https://download.docker.com/linux/static/stable/aarch64/) ；Compose [https://github.com/docker/compose/releases](https://github.com/docker/compose/releases)  

能出网的机器可直接：

```bash
mkdir -p /opt/docker-install && cd /opt/docker-install
curl -fL -o docker-24.0.9.tgz \
  https://download.docker.com/linux/static/stable/aarch64/docker-24.0.9.tgz
curl -fL -o docker-compose-linux-aarch64 \
  https://github.com/docker/compose/releases/download/v2.29.7/docker-compose-linux-aarch64
```

**③ 装 Docker 引擎：**

```bash
cd /opt/docker-install
tar -xzf docker-24.0.9.tgz
cp docker/* /usr/bin/
chmod +x /usr/bin/docker /usr/bin/dockerd /usr/bin/containerd /usr/bin/runc \
  /usr/bin/ctr /usr/bin/docker-proxy /usr/bin/containerd-shim-runc-v2 2>/dev/null || true

cat >/usr/lib/systemd/system/docker.service <<'EOF'
[Unit]
Description=Docker Application Container Engine
After=network-online.target firewalld.service
Wants=network-online.target

[Service]
Type=notify
ExecStart=/usr/bin/dockerd
ExecReload=/bin/kill -s HUP $MAINPID
LimitNOFILE=infinity
LimitNPROC=infinity
TimeoutStartSec=0
Delegate=yes
KillMode=process
Restart=on-failure
StartLimitBurst=3
StartLimitInterval=60s

[Install]
WantedBy=multi-user.target
EOF

mkdir -p /etc/docker
cat >/etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://docker.m.daocloud.io"],
  "log-driver": "json-file",
  "log-opts": { "max-size": "100m", "max-file": "3" },
  "data-root": "/var/lib/docker"
}
EOF
# 数据盘大时可把 data-root 改到 /data/docker（先 mkdir）

systemctl daemon-reload
systemctl enable --now docker
docker version
```

**④ 装 Compose：**

```bash
cd /opt/docker-install
mkdir -p /usr/local/lib/docker/cli-plugins
cp docker-compose-linux-aarch64 /usr/local/lib/docker/cli-plugins/docker-compose
chmod +x /usr/local/lib/docker/cli-plugins/docker-compose
ln -sf /usr/local/lib/docker/cli-plugins/docker-compose /usr/local/bin/docker-compose

docker compose version
docker run --rm hello-world   # 验证（会拉 aarch64 的 hello-world）
```

## A4. .51 启动中间件（Redis + OM/DS/Kettle…）

> **业务主库与分层库已在 .56 / .16 / .15，不在本机。**  
> `.51` 上 `prod_up_mid.sh` 默认仍会起 `sc_mid_mysql`（编排遗留）；**应用不连它**。可保留作闲置，或起完后 `docker stop sc_mid_mysql`。真正必开的是 **Redis**；治理/BI/调度/ETL 再 `--all`。  
> 镜像不用手动 pull：Compose 本地没有会自动拉。

**① 启动：**

```bash
cd /opt/chengde/chengde-smart-city
chmod +x scripts/prod_up_mid.sh

# 默认：Redis（+ 可选本机 mysql 容器，应用不用）
./scripts/prod_up_mid.sh

docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
# 至少应有 sc_mid_redis healthy
```

内存够再开全栈：

```bash
# ES / OpenMetadata / DataEase / DS / Kettle / Canal + 组件元库 oss-mysql:3307
./scripts/prod_up_mid.sh --all
```

**② 自检：**

```bash
# Redis（密码见 compose/prod-mid.env 的 REDIS_PASSWORD；须与 prod-app.env 一致）
docker exec -it sc_mid_redis redis-cli -a '<REDIS_PASSWORD>' ping
# 期望 PONG

# 全栈后再查（未 --all 可跳过）
curl -sf http://127.0.0.1:8585/api/v1/system/version | head -c 200; echo
```

**③（可选）提前拉镜像**

## A5. .55 启动门户

前提：

1. `.51` 上 **Redis** 已通（OM/DS/Kettle 若要用相关功能再 `--all`）。
2. 库机 **.56 / .16 / .15** 已建库、账号可连；`compose/prod-app.env` 已按方案 B 填好 `MYSQL_`* 与 `LAYER_*`（示例见 `prod-app.env.example`）。

```bash
cd /opt/chengde/chengde-smart-city
# 加载 A1 打好的应用镜像
docker load -i /path/to/chengde-app-images_*.tar

# 确认 env：控制面 .56、分层 .16/.15、中间件指向 .51
grep -E '^(MYSQL_|LAYER_|REDIS_|KETTLE_|UPLOAD_|ARCHIVE_)' compose/prod-app.env | sed 's/PASSWORD=.*/PASSWORD=***/'

# 附件 + 归档永久落盘（宿主机目录绑定进容器；勿只写容器可写层）
# backend 镜像以 uid 10001（appuser）运行，目录必须给该 uid 写权限，仅 chmod 755 且属主 root 会 Permission denied
mkdir -p /data/smart-city/uploads /data/smart-city/archives
chown 10001:10001 /data/smart-city/uploads /data/smart-city/archives
chmod 755 /data/smart-city/uploads /data/smart-city/archives

chmod +x scripts/prod_up_app.sh
./scripts/prod_up_app.sh
# 等价: docker compose -f compose/prod-app.yml --env-file compose/prod-app.env up -d
```

> 附件：宿主机 `/data/smart-city/uploads`（`UPLOAD_HOST_DIR`）→ 容器 `/data/uploads`（`APP_UPLOAD_DIR`）。资产目录附件在子目录 `asset-catalog/`。  
> 归档：宿主机 `/data/smart-city/archives`（`ARCHIVE_HOST_DIR`）→ 容器 `/data/archives`（`APP_ARCHIVE_DIR`）。现场 `prod-app.env` 须有这两项（示例见 `prod-app.env.example`）。备份库手工建库与权限说明见 [C6](#c6-存储生命周期备份归档销毁)。

# B. 后续更新部署

**每次发版固定顺序：**

```text
1. 判断改了什么（下表）→ 本机打对应包
2. 现场先做 B0 备份（必做）
3. 再按 B1 / B2 / B3 更新
4. 验收不过 → 按 B5 回退
```


| 你改了什么                                                                                             | 要重打             | 现场怎么更新                               |
| ------------------------------------------------------------------------------------------------- | --------------- | ------------------------------------ |
| **只改前端/后端代码**（`platform-frontend/`、`platform-backend/src/`**、`application-prod.yml`、Dockerfile 等） | 应用镜像            | B0 → **B1**（.55）                     |
| **只改配置/编排**（`compose/prod-*.yml`、`prod-*.env`、`scripts/`、分层连接相关）                                  | 代码包             | B0 → **B2**（改 mid→.51；改 app/env→.55） |
| **两者都改**                                                                                          | 镜像 + 代码包        | B0 → 先 **B2** 再 **B1**               |
| **只改库机/中间件密码或 `LAYER_*`/`MYSQL_*`**                                                               | 代码包（或直接改现场 env） | B0 → **B3**                          |


> 每次发版前请先把改动 **push 到远程**；打包/打镜像以 `origin/<分支>` 为准，本地未 push 的内容不会进包。  
> **本机** `release/` **里的旧** `*.tar` **/** `*.tar.gz` **不要删**，至少保留最近 2～3 次，回退时要靠它们。  
> **业务库在 .56 / .16 / .15**，备份与回退 **不要** 再对 `.51` 的 `sc_mid_mysql` 做业务 dump（除非你确认仍在用那套闲置库）。

## B0. 发版前备份（必做：镜像 + 代码；库 dump 默认不做）

备份目录建议：`/opt/chengde/backup/YYYYMMDD_HHMM`（.55 / .51 各自建）。

**发版策略（2026-08-19）：**

| 项 | 是否必做 | 说明 |
|----|:------:|------|
| ① 应用镜像 `app-images-prev.tar` | **必做** | `prod_deploy_on_57.sh` / 一键脚本自动做 |
| ③ 代码目录 `chengde-smart-city-prev.tar.gz` + `prod-*.env` | **必做** | 同上 |
| ② 业务库 / 分层库 mysqldump | **默认不做** | 跳过，避免现场 `docker run mysql:8.0` 拉镜像卡住；加表加列一般可继续用现库。一键脚本默认 `SKIP_DB_BACKUP=1` |

> 确需库 dump（破坏性 DDL / 必须能按 dump 回库）时：现场手工做下面 **②**，或显式 `SKIP_DB_BACKUP=0`（且本机已有 `mysql:8.0`，勿依赖临时 pull）。

**① .55 — 备份当前应用镜像（换镜像前必做）**

```bash
STAMP=$(date +%Y%m%d_%H%M)
mkdir -p /opt/chengde/backup/$STAMP
cd /opt/chengde/backup/$STAMP

docker tag smart-city/platform-backend:local smart-city/platform-backend:prev
docker tag smart-city/platform-frontend:local smart-city/platform-frontend:prev
docker save -o app-images-prev.tar \
  smart-city/platform-backend:prev \
  smart-city/platform-frontend:prev

docker images 'smart-city/platform-*' --format 'table {{.Repository}}\t{{.Tag}}\t{{.ID}}\t{{.CreatedSince}}' \
  | tee images-before.txt
```

**② 备份业务库 / 分层库（默认跳过；仅特殊需要时手工做）**

在 **能访问 56/16/15:13306** 的机器上执行。  
**注意：** `docker run mysql:8.0 …` 会在本地没有该镜像时去 Docker Hub 拉取，内网易卡住——须事先 `docker load` 好 `mysql:8.0`，或改用已有客户端。  
密码、账号以现场 `compose/prod-app.env` 为准：

```bash
STAMP=$(date +%Y%m%d_%H%M)
mkdir -p /opt/chengde/backup/$STAMP
cd /opt/chengde/backup/$STAMP

# 从 prod-app.env 读连接（须去掉 Windows CRLF 的 \r，否则端口形如 13306\r 导致 mysqldump 失败）
ENV=/opt/chengde/chengde-smart-city/compose/prod-app.env
# 现场 env 若仍是 CRLF，先规范化一次（可重复执行）
if grep -q $'\r' "$ENV" 2>/dev/null; then
  sed -i 's/\r$//' "$ENV"
fi
MYSQL_HOST=$(grep '^MYSQL_HOST=' $ENV | cut -d= -f2- | tr -d '\r')
MYSQL_PORT=$(grep '^MYSQL_PORT=' $ENV | cut -d= -f2- | tr -d '\r')
MYSQL_USER=$(grep '^MYSQL_USER=' $ENV | cut -d= -f2- | tr -d '\r')
MYSQL_PASSWORD=$(grep '^MYSQL_PASSWORD=' $ENV | cut -d= -f2- | tr -d '\r')
LAYER_ODS_HOST=$(grep '^LAYER_ODS_HOST=' $ENV | cut -d= -f2- | tr -d '\r')
LAYER_ODS_PORT=$(grep '^LAYER_ODS_PORT=' $ENV | cut -d= -f2- | tr -d '\r')
LAYER_ODS_USER=$(grep '^LAYER_ODS_USER=' $ENV | cut -d= -f2- | tr -d '\r')
LAYER_ODS_PASSWORD=$(grep '^LAYER_ODS_PASSWORD=' $ENV | cut -d= -f2- | tr -d '\r')
LAYER_DWS_HOST=$(grep '^LAYER_DWS_HOST=' $ENV | cut -d= -f2- | tr -d '\r')
LAYER_DWS_PORT=$(grep '^LAYER_DWS_PORT=' $ENV | cut -d= -f2- | tr -d '\r')
LAYER_DWS_USER=$(grep '^LAYER_DWS_USER=' $ENV | cut -d= -f2- | tr -d '\r')
LAYER_DWS_PASSWORD=$(grep '^LAYER_DWS_PASSWORD=' $ENV | cut -d= -f2- | tr -d '\r')

dump() {
  local host=$1 port=$2 user=$3 pass=$4 db=$5 out=$6
  docker run --rm mysql:8.0 mysqldump -h"$host" -P"$port" -u"$user" -p"$pass" \
    --single-transaction --routines --triggers "$db" > "$out"
}

# 控制面（必做）
dump "$MYSQL_HOST" "$MYSQL_PORT" "$MYSQL_USER" "$MYSQL_PASSWORD" smart_city smart_city.sql

# 分层仓（有汇聚/治理/融合数据时建议做；ODS/DWD 同机 .16，DWS/ADS 同机 .15）
dump "$LAYER_ODS_HOST" "$LAYER_ODS_PORT" "$LAYER_ODS_USER" "$LAYER_ODS_PASSWORD" smart_city_ods smart_city_ods.sql
dump "$LAYER_ODS_HOST" "$LAYER_ODS_PORT" "$LAYER_ODS_USER" "$LAYER_ODS_PASSWORD" smart_city_dwd smart_city_dwd.sql
dump "$LAYER_DWS_HOST" "$LAYER_DWS_PORT" "$LAYER_DWS_USER" "$LAYER_DWS_PASSWORD" smart_city_dws smart_city_dws.sql
dump "$LAYER_DWS_HOST" "$LAYER_DWS_PORT" "$LAYER_DWS_USER" "$LAYER_DWS_PASSWORD" smart_city_ads smart_city_ads.sql

ls -lh *.sql
```

| 本机打镜像/打包脚本中文乱码或语法错误                               | Windows PowerShell 5.1 须用 **UTF-8 BOM** 的 `.ps1`；请用仓库内最新 `scripts/build_prod_images.ps1` / `pack_prod_release.ps1`，或双击对应 `.bat`（已 `chcp 65001`） |
| Docker 命令失败：`dockerDesktopLinuxEngine` / pipe 不存在 | **Docker Desktop 未启动**。本机路径常见为 `%LOCALAPPDATA%\Programs\DockerDesktop\Docker Desktop.exe`，启动后再 `docker info`                                    |
| B0 备份 mysqldump 报 `Unknown suffix` / 端口 `13306\r` | `prod-*.env` 为 **CRLF**。本机打包脚本已强制输出 **LF**；现场 `prod_up_*.sh` 会自动 `sed` 去 `\r`；B0 读 env 须 `tr -d '\r'`                                           |
| SSH 连不上 .55 / .51                                 | 账号 `root`，口令见 [D27](D27-生产环境数据库与中间件账号密码清单.md)；本机需能访问 `10.10.10.0/24`                                                                            |
| 归档/附件 `Permission denied` / 写不进盘                     | 宿主机目录属主仍是 root、权限 755，而容器进程是 **uid 10001**。按 C6 执行 `chown 10001:10001` 后重建 backend；不要只 `chmod 755` |
| 定时备份报找不到备份库 / Unknown database                      | 备份库须**现场手工创建**（C6），且与源库同机；不要只在 .56 建 ods/dws 的 bak |


## C6. 存储生命周期（备份 / 归档 / 销毁）

对照代码迭代 [D17 R93](D17-系统优化流程及方式.md)（R89 建库/挂盘步骤仍有效；R91 月快照已改为按日 `yyyyMMdd`）。**备份库由现场手工创建**；应用发版后还须挂盘、赋权、配环境、重建容器，并在页面启动定时策略。`.51` / `.12` 不用为此改。

### C6.1 备份库（现场手工，可重复执行）

在对应库机 MySQL **13306** 执行仓库脚本（`CREATE DATABASE IF NOT EXISTS`，可重复跑）。账号与源库相同，见 [D27](D27-生产环境数据库与中间件账号密码清单.md)。


| 主机            | 脚本                                             | 库名                                       |
| ------------- | ---------------------------------------------- | ---------------------------------------- |
| `10.10.10.56` | `sql/patch/20260816_create_bak_on_56.sql`      | `smart_city_bak`                         |
| `10.10.10.16` | `sql/patch/20260816_create_bak_on_16.sql`      | `smart_city_ods_bak`、`smart_city_dwd_bak` |
| `10.10.10.15` | `sql/patch/20260816_create_bak_on_15.sql`      | `smart_city_dws_bak`、`smart_city_ads_bak` |


上线**不要依赖**应用首次备份时自动建库。`.12` 指标库不在五库范围内，**不建** bak。

### C6.2 应用机 `.57`：归档目录权限与挂载

backend 镜像 `USER appuser`，**uid/gid = 10001**。绑定挂载后容器内看到的属主就是宿主机属主：目录若属 `root:root` 且 `755`，容器**只能读、不能写**。

必须同时满足：

1. 目录存在（`mkdir -p`）
2. **uid 10001 对目录有写权限**（推荐 `chown 10001:10001`，`chmod 755`）
3. 目录有进入权限（`x` 位）；写出 gzip 还要有写权限（`w`）
4. `prod-app.yml` 已把宿主机目录挂到容器 `/data/archives`，改卷后须 **重建** `sc_app_backend`（只 `restart` 不够）

**禁止**用 `chmod 777` 凑合；**不要**把归档写进容器可写层（重建即丢）。

```bash
# .57
mkdir -p /data/smart-city/uploads /data/smart-city/archives
chown 10001:10001 /data/smart-city/uploads /data/smart-city/archives
chmod 755 /data/smart-city/uploads /data/smart-city/archives

# prod-app.env 须含（无则补上后再 prod_up_app.sh）
# ARCHIVE_HOST_DIR=/data/smart-city/archives
# APP_ARCHIVE_DIR=/data/archives

./scripts/prod_up_app.sh

# 确认挂载
docker inspect sc_app_backend --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{println}}{{end}}'
# 应有：/data/smart-city/archives -> /data/archives

# 确认 uid 10001 可写（应成功且无 Permission denied）
docker exec -u 10001 sc_app_backend sh -c 'touch /data/archives/.write_test && rm /data/archives/.write_test'
```

磁盘：备份日快照表涨在 **.56/.16/.15** 的 MySQL 数据盘；gzip 涨在 **.57** `/data/smart-city/archives`。销毁策略只删**满 6 个月**的备份表 `{表}{yyyyMMdd}` 与归档 `{表}{yyyyMMdd}.tsv.gz`，**不会改源业务表**。

### C6.3 发版后页面配置

功能不会自动跑。登录门户 → **大数据平台资源中心 → 数据库存储管理**，选源库、**多选表**、选执行周期，点 **启动**。仅定时触发。备份在 `{源库}_bak` 生成**当天** `{表名}{yyyyMMdd}`（源表不改；每天/每周/每月跑都是这一天的日期，不是一律按月）；归档同名 `tsv.gz`；销毁按该时间戳且须满 6 个月。分区方式只记台账。

验收：到期后对应 `*_bak` 有 `A20260816` 这类日快照表；`.57` `ls /data/smart-city/archives` 能看到 `A20260816.tsv.gz`；满 6 个月销毁后快照表和文件消失，源表仍在。
