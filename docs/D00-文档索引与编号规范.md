## 一、编号规则

本项目文档分两个系列，**均在本表登记**：

### 1.1 D 系列 — 正式工程文档

| 规则项 | 约定 |
|--------|------|
| **前缀** | `D` + 两位序号，如 `D01`、`D07` |
| **文件名** | `D{nn}-{文档简称}.md`，与下表「文件名」列一致 |
| **正文元数据** | 各文档属性表首行须含 `**文档编号** \| **D{nn}** \|` |
| **版本号** | 独立于文档编号；格式仍为 V1.0、V2.2 等 |
| **序号分配** | 按**工程流程顺序**递增；已占用序号不得复用 |
| **新增文档** | ① 取下一个空闲序号 → ② 按规范命名文件 → ③ 在本表登记 → ④ 更新 `D02` 第十三节文档链 |
| **存放位置** | 仓库 `docs/`（工程文档主目录） |

### 1.2 P 系列 — 过程文档（审阅报告 / 分析报告 / 早期版本）

| 规则项 | 约定 |
|--------|------|
| **前缀** | `P` + 两位序号，如 `P01`、`P14` |
| **文件名** | `P{nn}-{文档简称}.md`，与下表「文件名」列一致 |
| **正文元数据** | 各文档属性表首行须含 `**文档编号** \| **P{nn}** \|` |
| **序号分配** | 按**工程逻辑顺序**递增；已占用序号不得复用 |
| **新增文档** | ① 取下一个空闲序号 → ② 按规范命名文件 → ③ 在本表 P 系列区登记 |
| **存放位置** | `C:\Users\ming\WorkBuddy\2026-06-22-16-59-17\`（WorkBuddy 工作目录） |
| **与 D 系列关系** | 每份 P 文档标注其**关联 D 文档**；P 文档是 D 文档的编制输入、审阅反馈或前身版本 |

**不在本编号体系内**：甲方 Word 原件（`docs/requirements/`）、厂商接口 docx（`docs/vendor/`）、`docs/extracts/` 等原始素材；`scripts/` 内脚本说明可另附注释，不强制 D/P 编号。
