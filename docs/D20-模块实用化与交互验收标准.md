## 一、定位与完成度维度

| 维度（原称） | 口径 | 说明 |
|:------:|------|------|
| **底线**（曾称 P0） | D02 / D05 / V3.0 功能清单 | 能力、边界、验收编号（Mxxx）必须覆盖；不得用演示假数据冒充验收 |
| **友好可用**（曾称 P1） | 交互与可操作性 | 业务人员可不看文档完成主路径；少手填、少英文、少死胡同、可解释 |
| **运维增强**（曾称 P2） | 运维与扩展 | 监控、日志、幂等、分层库、外部组件健康检查 |

### 1.1 交付节奏（2026-07-25 起强制，至项目结束）

**不再按 P0 / P1 / P2 分期交付或分期收工。**

- 上表三项是「什么叫做完」的检查维度，**不是**排期阶段。
- 每一轮模块改造须对该模块**最终目标一次做全**（底线 + 友好可用 + 本模块所需运维能力一并落地）。
- 禁止「先薄演示、后补友好」「本轮只做 P0、P1 以后再说」写入代码或 D17。
- 范围过大时：缩小**模块边界**后仍做全该边界，而不是降级为演示版。

**原则**：禁止「菜单能点、链路不通」的薄演示交付；与 D17 分块优化兼容——分块指子系统边界，不是降低完成度。

### 2.4 数据治理 ETL（主数据 · 2.1，D17 R10 + 本轮增量）

| 主题 | 补充要点 |
|------|----------|
| 执行引擎 | **仅 Kettle/Carte**；已移除 JVM 内存拓扑执行（`GovernanceExecuteService` / `FusionExecuteService`） |
| 画布交互 | 组件属性 **双击弹窗**；右侧属性栏取消，画布占满；选中态用节点内光晕而非粗外框 |

| 字段 | 下游组件字段下拉从探表/上游自动带入；禁空下拉误导为「只能手填」 |
| 脱敏 MASK | Kettle `ScriptValueMod` + 声明 `fields/replace`；MD5 / 日期类字段 **强制写新列**；运行前目标表自动补 `VARCHAR` 列 |
| 「查看数据」 | **只读治理后 DWD/DWS/ADS 输出表**，禁止展示 ODS 原始层冒充结果 |
| 落表 | 平台 `ensureOutputTables` 按源表 `LIKE` 建目标表；新建任务默认倾向清空后写入 |
| 监控 | 实例列表与节点过程左右布局（左宽右窄）；过程摘要中文化（已完成 · 秒 · 行/秒）；总时长为墙钟，与步骤秒数非简单相加 |
| Carte 端口 | 本机宿主映射优先 `18081`（避开 Windows 8081 保留段），见 D18 / `local.env.example` |

### 2.5 质量与融合分层（2026-07-25 · 过程 vs 资源）

| 主题 | 要点 |
|------|------|
| 产品口径 | 见 D07 §9.3.1：治理→过程数据；融合→主题/专题资源；目录只挂可共享资源；直通源亦可编目 |
| 质量选库 | 来源库按源层/过程层/资源层分组；页面提示是否可进目录 |

## 三、后续模块改造总则（必须遵守）

### 3.1 改造顺序（与 D17 R9 一致）

```text
1. 划清业务边界与对象主键（谁写哪一层、不搬什么数据）
2. 打通真实数据流（登记对象 → 探库/任务 → 落库 → 可回看）
3. 补齐任务 / 监控 / 版本 / 目录或分析闭环
4. 打磨交互（少手填、中文、可解释、无死胡同）
5. 更新 D17 迭代记录 + 本标准符合性自检
```

### 3.2 数据与边界

1. **控制面 / 数据面分离**：`smart_city`（`sys_*` / `ing_*` / `gov_*`）vs ODS/DWD/DWS/ADS。
2. **禁止重复录入连接信息**：后续模块只能选已登记数据源/表/资产。
3. **引擎职责清晰**：搬运与重转换优先 Kettle（或既定引擎）；平台不做「第二套内存治理」平行实现。
4. **占位配置不得进生产路径**：禁止默认 `table_name` / `output_table` / `/tmp/xxx` 在未校验情况下执行。
5. **查看结果 = 业务落层结果**：预览接口不得默默退回源表/ODS。

### 3.3 交互与展示（友好可用硬门槛）

| 规则 | 要求 |
|------|------|
| 状态/枚举 | 展示走 `statusLabel` / `$statusLabel`；API 仍传英文码 |
| 工具栏表单 | `portal-inline-form` + 字段宽度类；禁止 inline 散落 `style="width"` |
| 加载 | 按当前 Tab/步骤加载；并行 ≤3；Hub `keep-alive`；变更后局部刷新 |
| 选择优先于手填 | 表/字段/数据源：可搜索下拉；允许「自定义」为次要开关 |
| 属性编辑 | 复杂画布组件优先双击弹层，保证画布可视面积 |
| 英文运维信息 | 面向业务的摘要必须中文化（Finished→已完成，r/s→行/秒 等）；完整英文日志可下钻查看 |
| 超级管理员 | `sys_admin` 永不被授权过滤挡在门外 |

### 3.4 执行、错误与可观测

1. 运行前校验（缺表、缺数据源、输出未落 DWD 等）必须 **中文可读**。
2. 类型不安全的变换（如 MD5 写入 DATE）必须 **强制新列或拦截**，不得等数据库报错。
3. 监控须同时有：实例级墙钟时长 + 步骤级过程摘要；二者语义在界面可区分（见 §2.4）。
4. 失败日志可下钻；成功后「查看数据」直达治理输出层。

### 3.5 前端 API 与权限

1. 契约字段名与后端一致；改契约先告知并改文档。
2. `@PreAuthorize` + 业务内 `isSystemAdmin()` 放行逻辑齐全。
3. Java **无 Lombok**；改完可 `mvn compile`。

## 四、模块交付符合性清单（后续模块必勾）

改造完成宣称「可用」前，至少勾选：

- [ ] D05 对应 M 编号主路径可真实跑通（非纯 MOCK）
- [ ] 数据源/表/字段以选择为主，无强制重复填 JDBC
- [ ] 写入分层正确；「查看结果」读的是目标层而非源层
- [ ] 状态/枚举已中文化；工具栏符合 `portal-inline-form`
- [ ] 首屏并行请求 ≤3；Tab 切换不无差别全量 reload
- [ ] 占位默认值无法绕过校验直接执行
- [ ] 若依赖 Kettle/Carte：健康检查失败时明确 503/中文提示，无静默内存回退
- [ ] 敏感变换（脱敏/哈希）不破坏原列类型，或已自动新列 + DDL
- [ ] 监控/日志对业务可读；运维原文可下钻
- [ ] 已更新 D17 迭代记录，并在本标准清单自检
- [ ] 过程层(DWD)未误当目录资源；融合产出明确落主题/专题；质量门禁与直通/加工路径匹配
