## 怎么用这份手册

- **第一次上线** → 看 **A. 初次部署**（从装 Docker 到跑通，按顺序做完）。
- **以后改了代码/配置再发版** → 看 **B. 后续更新部署**：**先 B0 备份**，再按改动做 B1/B2/B3；失败则 **B5 回退**。
- 机器信息、端口、运维、排障在 **C. 附录**。

**方案要点：**

1. 仅 **Docker + Compose** 用离线包装（麒麟 yum 装不好）；MySQL/Redis/中间件/门户**全跑在容器里**，不 yum 装。
2. 现场 Docker **能出网**：中间件镜像在 .51 直接 `docker pull`；门户前后端镜像由**本机**打好后 `docker load` 到 .55（现场不 build）。
3. 代码 + 配置（含 `prod-*.env`）由**本机打包**离线投递，服务器不依赖 `git`。
4. ESB 外挂 **10.10.10.61:7000**，不在本方案内。

| 机器 | IP | 职责 | 编排文件 |
|------|-----|------|---------|
| 应用 | 10.10.10.55 | 门户 web + backend | [`compose/prod-app.yml`](../compose/prod-app.yml) |
| 库+中间件 | 10.10.10.51 | MySQL / Redis / OM / DS / Kettle / ES… | [`compose/prod-mid.yml`](../compose/prod-mid.yml) |

# A. 初次部署

一次性走完下面 6 步即可上线。

```text
本机打包            →  A1  产出：代码包 + 应用镜像
两机装 Docker       →  A2  .51 / .55 各装一遍
投递代码 + 防火墙   →  A3
.51 起库+中间件     →  A4
.55 起门户          →  A5
验收                →  A6
```

## A1. 本机打包（办公电脑，可出网）

> 生产密码文件 `compose/prod-mid.env` / `prod-app.env` 仓库里**已有**，打包脚本会自动带上，现场不用改。要换新密码：`.\scripts\gen_prod_env.ps1 -Force`。  
> **统一输出目录：** 仓库根下 `release/`（脚本自动创建；已 gitignore，不会进 git）。代码包与应用镜像都放这里。

**① 打代码包**（先把要上线的改动 **push 到远程**，打包读的是 `origin/<分支>`，不是本机工作区）：

双击 `scripts\pack_prod_release.bat` → 输入远程分支名。
或命令行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\pack_prod_release.ps1 -Branch feature_yxj
```

脚本会先 `git fetch origin <分支>`，再按远程提交打 `release/chengde-smart-city_<分支>_<sha>_<时间>.tar.gz`（仅 `compose/` + `scripts/prod_up_*` + 本机 `prod-*.env`；**不含** docs / catalog / 前后端源码）。

**② 打应用镜像**（本机需已启动 Docker Desktop；同样先 fetch 远程分支）：

双击 `scripts\build_prod_images.bat` → 输入远程分支名。

产出到 `release/`：`chengde-app-images_<分支>_<sha>_<时间>.tar`（前后端镜像 `smart-city/platform-*:local`）。

从 `release/` 把这两个文件拷到 U 盘 / 通过内网传到服务器（建议至少保留最近 2～3 次，方便回退）。

## A2. 两台机装 Docker + Compose（离线）

**.51 和 .55 都要做一遍。**

**① 检查环境：**

```bash
cat /etc/os-release    # V10 (Lance)
uname -m               # 须为 x86_64（与安装包一致）
yum remove -y podman docker-runc 2>/dev/null || true
```

**② 准备两个安装包**（x86_64），上传到 `/opt/docker-install/`：

| 文件 | 说明 |
|------|------|
| `docker-24.0.9.tgz` | Docker 引擎静态包 |
| `docker-compose-linux-x86_64` | Compose（GitHub Assets，勿选 darwin/windows） |

**③ 装 Docker 引擎：**

```bash
cd /opt/docker-install
tar -xzf docker-24.0.9.tgz
cp docker/* /usr/bin/
chmod +x /usr/bin/docker /usr/bin/dockerd /usr/bin/containerd /usr/bin/runc \
  /usr/bin/ctr /usr/bin/docker-proxy /usr/bin/containerd-shim-runc-v2 2>/dev/null || true

cat >/usr/lib/systemd/system/docker.service <<'EOF'
[Unit]
Description=Docker Application Container Engine
After=network-online.target firewalld.service
Wants=network-online.target

[Service]
Type=notify
ExecStart=/usr/bin/dockerd
ExecReload=/bin/kill -s HUP $MAINPID
LimitNOFILE=infinity
LimitNPROC=infinity
TimeoutStartSec=0
Delegate=yes
KillMode=process
Restart=on-failure
StartLimitBurst=3
StartLimitInterval=60s

[Install]
WantedBy=multi-user.target
EOF

mkdir -p /etc/docker
cat >/etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://docker.m.daocloud.io"],
  "log-driver": "json-file",
  "log-opts": { "max-size": "100m", "max-file": "3" },
  "data-root": "/var/lib/docker"
}
EOF
# 数据盘大时可把 data-root 改到 /data/docker（先 mkdir）

systemctl daemon-reload
systemctl enable --now docker
docker version
```

**④ 装 Compose：**

```bash
cd /opt/docker-install
mkdir -p /usr/local/lib/docker/cli-plugins
cp docker-compose-linux-x86_64 /usr/local/lib/docker/cli-plugins/docker-compose
chmod +x /usr/local/lib/docker/cli-plugins/docker-compose
ln -sf /usr/local/lib/docker/cli-plugins/docker-compose /usr/local/bin/docker-compose

docker compose version
docker run --rm hello-world   # 验证
```

## A4. .51 启动库与中间件

> **镜像不用手动 pull。** `prod_up_mid.sh` 内部是 `docker compose -f compose/prod-mid.yml up -d`，Compose 读 yml 里的 `image:`，本地没有会**自动从网上拉**。Docker 有网就直接看第 ① 步。

**① 启动（会自动拉镜像 + 建库）：**

```bash
# 进入部署目录（代码包解压后的路径）
cd /opt/chengde/chengde-smart-city

# 给启动脚本加可执行权限（只需做一次）
chmod +x scripts/prod_up_mid.sh

# 启动 MySQL + Redis；本地没有镜像时自动 pull（mysql:8.0、redis:7-alpine）
# 首次启动会按 init 脚本自动建库：smart_city / ods / dwd / dws / ads
# 业务用户 smart_city，密码见 compose/prod-mid.env
./scripts/prod_up_mid.sh

# 查看容器是否起来：应有 sc_mid_mysql、sc_mid_redis；MySQL 宿主端口 13306
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
```

内存够再开全栈：

```bash
# 在 MySQL/Redis 已通的基础上，再起 ES / OpenMetadata / DataEase / DS / Kettle / Canal
# 同样会按 prod-mid.yml 自动 pull 缺的镜像
./scripts/prod_up_mid.sh --all
```

**② 自检：**

```bash
# 进 MySQL 容器，列出以 smart_city 开头的库（应能看到主库和分层库）
# -p 后会提示输入密码，填 prod-mid.env 里的 MYSQL_PASSWORD
docker exec -it sc_mid_mysql mysql -usmart_city -p -e "SHOW DATABASES LIKE 'smart_city%';"

# 进 Redis 容器做 ping；-a 后面换成 prod-mid.env 里的 REDIS_PASSWORD，期望返回 PONG
docker exec -it sc_mid_redis redis-cli -a '<prod-mid.env 里的 REDIS_PASSWORD>' ping
```

**③（可选）提前拉镜像 / 核对失败项**

想在启动前先把镜像拉齐、或某个镜像总拉不下来想单独重试时，才手动执行；完整镜像清单见 [C2](#c2-中间件镜像清单)：

```bash
# 只起库+缓存时，拉这两个就够（也可跳过，交给 prod_up_mid.sh 自动拉）
docker pull mysql:8.0
docker pull redis:7-alpine

# 开全栈再按 C2 拉其余镜像（ES / Seaweed / Mongo / OM / DataEase / DS / Kettle / Canal）
```

# B. 后续更新部署

**每次发版固定顺序：**

```text
1. 判断改了什么（下表）→ 本机打对应包
2. 现场先做 B0 备份（必做）
3. 再按 B1 / B2 / B3 更新
4. 验收不过 → 按 B5 回退
```

| 你改了什么 | 要重打 | 现场怎么更新 |
|------------|--------|--------------|
| **只改前端/后端代码**（`platform-web/**`、`platform-backend/src/**`、`application-prod.yml`、`nginx.conf`、Dockerfile） | 应用镜像 | B0 → **B1**（.55） |
| **只改配置/编排**（`compose/prod-*.yml`、`prod-*.env`、`scripts/`、`init-prod-mysql.sql`） | 代码包 | B0 → **B2**（改 mid→.51；改 app→.55） |
| **两者都改** | 镜像 + 代码包 | B0 → 先 B2 再 B1 |
| **只改数据库密码等 env** | 代码包（或直接改现场 env） | B0 → **B3** |

> 每次发版前请先把改动 **push 到远程**；打包/打镜像以 `origin/<分支>` 为准，本地未 push 的内容不会进包。  
> **本机 `release/` 里的旧 `*.tar` / `*.tar.gz` 不要删**，至少保留最近 2～3 次，回退时要靠它们。

## B0. 发版前备份（必做）

备份目录建议：`/opt/chengde/backup/YYYYMMDD_HHMM`（两机各自建）。

**① .55 — 备份当前应用镜像（换镜像前必做）**

```bash
# 建本次备份目录（把日期时间换成实际值）
STAMP=$(date +%Y%m%d_%H%M)
mkdir -p /opt/chengde/backup/$STAMP
cd /opt/chengde/backup/$STAMP

# 把正在跑的 :local 打成 :prev，并导出成文件（回退用）
docker tag smart-city/platform-backend:local smart-city/platform-backend:prev
docker tag smart-city/platform-web:local     smart-city/platform-web:prev
docker save -o app-images-prev.tar \
  smart-city/platform-backend:prev \
  smart-city/platform-web:prev

# 记下当前容器用的镜像 ID，方便核对
docker images 'smart-city/platform-*' --format 'table {{.Repository}}\t{{.Tag}}\t{{.ID}}\t{{.CreatedSince}}' \
  | tee images-before.txt
```

**② .51 — 备份业务库（凡可能触发 Flyway / 改库结构时必做；纯前端改动可跳过）**

```bash
STAMP=$(date +%Y%m%d_%H%M)
mkdir -p /opt/chengde/backup/$STAMP
cd /opt/chengde/backup/$STAMP

# 导出业务主库（-p 后输入 prod-mid.env 里的 MYSQL_PASSWORD）
docker exec sc_mid_mysql mysqldump -usmart_city -p \
  --single-transaction --routines --triggers \
  smart_city > smart_city.sql

# 如有分层仓重要业务数据，一并导出（按需）
# docker exec sc_mid_mysql mysqldump -usmart_city -p smart_city_ods > smart_city_ods.sql
# docker exec sc_mid_mysql mysqldump -usmart_city -p smart_city_dwd > smart_city_dwd.sql
# docker exec sc_mid_mysql mysqldump -usmart_city -p smart_city_dws > smart_city_dws.sql
# docker exec sc_mid_mysql mysqldump -usmart_city -p smart_city_ads > smart_city_ads.sql

ls -lh *.sql
```

**③ 两机 — 备份当前代码目录（换代码包前必做）**

```bash
STAMP=$(date +%Y%m%d_%H%M)
mkdir -p /opt/chengde/backup/$STAMP

# 整目录打包当前部署树（含 compose/prod-*.env）
cd /opt/chengde
tar -czf backup/$STAMP/chengde-smart-city-prev.tar.gz chengde-smart-city

# 单独再留一份 env，防手误
cp -a chengde-smart-city/compose/prod-*.env backup/$STAMP/ 2>/dev/null || true
ls -lh backup/$STAMP/
```

备份齐了再进入下面的更新步骤。

## B1. 只改了前后端代码 → 换应用镜像（.55）

**本机：**

```powershell
# 双击 scripts\build_prod_images.bat 输入分支名，或：
powershell -ExecutionPolicy Bypass -File .\scripts\build_prod_images.ps1 -Branch feature_yxj
# 产出 chengde-app-images_<分支>_<sha>_<时间>.tar（含 :local 与 :分支-sha 双标签）→ 在仓库 release/
```

**.55（先完成 B0①；若本次含 DB 迁移再做 B0②）：**

```bash
cd /opt/chengde/chengde-smart-city

# 加载新镜像（会覆盖 :local；:prev 与备份 tar 仍在，可回退）
docker load -i /path/to/chengde-app-images_*.tar

# 用新镜像重建 web + backend
./scripts/prod_up_app.sh

# 验收
docker ps
curl -s http://127.0.0.1/actuator/health
# 浏览器打开 http://10.10.10.55/ 抽查关键功能
```

> Flyway 有新迁移会在后端启动时自动执行；**一旦执行成功，单纯换回旧镜像不够，还要按 B5 恢复库备份。**

## B2. 只改了配置/编排 → 换代码包

**本机：** 双击 `scripts\pack_prod_release.bat` 输入分支名，得到 `release/chengde-smart-city_*.tar.gz`。

**现场（先完成 B0③；改 mid 且可能动库再做 B0②）：**

```bash
cd /opt/chengde

# 解压覆盖（旧目录已在 B0 打成 chengde-smart-city-prev.tar.gz）
tar -xzf /path/to/chengde-smart-city_*.tar.gz

cd chengde-smart-city
# 改的是 .51 中间件编排：
./scripts/prod_up_mid.sh          # 或 --all
# 改的是 .55 门户编排：
./scripts/prod_up_app.sh
```

`prod_up_*` 会按新的 yml/env 重建受影响的容器；未变的容器不受影响。

## B3. 只改数据库/中间件密码

先做 B0③（必要时 B0②）。两种做法二选一：

- **本机改**：编辑 `compose/prod-mid.env` / `prod-app.env`（两机密码要一致）→ 重打代码包 → 现场覆盖 → 重跑 `prod_up_*`。
- **现场改**：直接在两台机 `compose/prod-*.env` 改同一密码 → `prod_up_mid` / `prod_up_app`。

> 改 MySQL 密码若库已初始化，注意容器里的旧密码仍在数据卷内，需按 MySQL 改密流程处理，不能只改 env。

## B4. 常用即时操作

| 动作 | 机器 | 命令 |
|------|------|------|
| 重启后端 | .55 | `docker restart sc_app_backend` |
| 看日志 | .55/.51 | `docker logs -f sc_app_backend` / `sc_mid_mysql` |
| 临时备份库 | .51 | 见 B0② |
| 停中间件 | .51 | `docker compose -f compose/prod-mid.yml --env-file compose/prod-mid.env down`（**勿加 -v**，除非要清数据） |

现场**不要**用 `git pull` 发版，一律走本机打包投递。

## B5. 出问题如何回退

按「先停新版 → 恢复镜像/代码 → 必要时恢复库 → 再拉起」的顺序做。

**① 回退应用镜像（.55，对应 B1 失败）**

```bash
cd /opt/chengde/chengde-smart-city

# 方式 A：用发版前打的 :prev 标签（B0① 做过）
docker tag smart-city/platform-backend:prev smart-city/platform-backend:local
docker tag smart-city/platform-web:prev     smart-city/platform-web:local

# 方式 B：若 :prev 没了，从备份 tar 再 load
# docker load -i /opt/chengde/backup/<STAMP>/app-images-prev.tar
# 再执行上面两条 docker tag（load 后已有 :prev）

# 用旧镜像重建容器
./scripts/prod_up_app.sh
curl -s http://127.0.0.1/actuator/health
```

也可直接 `docker load` 本机保留的**上一次** `chengde-app-images_*.tar`，再 `prod_up_app.sh`。

**② 回退代码/配置（对应 B2 失败）**

```bash
cd /opt/chengde

# 先挪走有问题的目录（可事后再删）
mv chengde-smart-city chengde-smart-city.bad.$(date +%Y%m%d_%H%M)

# 解压 B0 备份的上一版
tar -xzf backup/<STAMP>/chengde-smart-city-prev.tar.gz

cd chengde-smart-city
./scripts/prod_up_mid.sh    # .51 需要时
./scripts/prod_up_app.sh    # .55 需要时
```

**③ 回退数据库（仅当本次发版跑过 Flyway / 改过表结构，且业务异常）**

```bash
# 先停 .55 后端，避免写入半新半旧数据
docker stop sc_app_backend

# 用 B0② 的 dump 覆盖恢复（会覆盖当前库数据，确认 STAMP 无误）
docker exec -i sc_mid_mysql mysql -usmart_city -p smart_city \
  < /opt/chengde/backup/<STAMP>/smart_city.sql

# 先按 ① 把镜像/代码回到旧版，再启动
docker start sc_app_backend
# 或：./scripts/prod_up_app.sh
```

> **注意：** Flyway 已成功执行的迁移，只换回旧镜像而不恢复库，旧代码可能因「表结构已是新版」而报错。有结构变更的发版，**镜像回退必须配套库回退**（或准备好向前修复脚本）。

**④ 回退后验收**

- `docker ps` 正常；`curl` 健康检查 OK  
- 登录门户抽查发版相关功能  
- 确认用的是旧镜像：`docker images 'smart-city/platform-*'` 看 ID 是否与 `images-before.txt` 一致

## C5. 常见问题

| 现象 | 处理 |
|------|------|
| dockerd 起不来 / 提到 podman | `yum remove -y podman` 后 `systemctl restart docker` |
| 拉镜像失败 | 检查出网与 `daemon.json` 加速器；按 A4 逐条 `docker pull` 看哪条失败 |
| .55 连不上 MySQL | 查防火墙、`13306`、env 密码、.51 上 `docker ps` |
| Compose 找不到 | 复查 A2④；脚本兼容 `docker compose` / `docker-compose` |
| .51 内存不够 | 先 `./scripts/prod_up_mid.sh`（不加 `--all`），再分批加 profile |
| 换镜像后仍是旧页面 | 确认 `docker load` 覆盖了 `:local`，再 `./scripts/prod_up_app.sh` 重建 |
| 发版后要回退 | 先按 B5；有 Flyway 结构变更时镜像回退必须配套库 dump 恢复 |
