## 〇、先读：MySQL / Redis 要不要单独 yum 安装？

**不要单独装。**

本方案约定：

1. 两台机先装好 **Docker + Compose**（本章 §二）。  
2. 再在 **.51** 用 Compose **拉起** MySQL、Redis、Kettle、OM…（容器即安装）。  
3. 在 **.55** 用 Compose 拉起 门户 web + backend。

你不用再执行 `yum install mysql redis`。装完 Docker 后，中间件都跟 Compose 走。

```text
裸机麒麟
  → §二 装 Docker/Compose（.51 与 .55 都要）
  → §三 防火墙 / 目录 / 代码
  → §四 .51 起 MySQL+Redis+中间件（自动新建库）
  → §五 .55 起应用
  → §六 验收
```

## 二、两台机都要：安装 Docker + Compose（麒麟 V10 Lance）

现场实测系统信息示例：

```text
NAME="Kylin Linux Advanced Server"
VERSION="V10 (Lance)"
ID="kylin"
VERSION_ID="V10"
PRETTY_NAME="Kylin Linux Advanced Server V10 (Lance)"
```

政务云多半**出网受限**，下面以 **离线二进制** 为主（Lance / SP3 均可用同一套办法；**不要依赖**官方「专为 Ubuntu/CentOS 写的一键脚本」硬套）。

### 2.1 环境检查（root）

```bash
cat /etc/os-release     # 确认 V10 (Lance)
uname -m                # x86_64 或 aarch64，下载包必须匹配
free -h
df -h
# 若装过 podman，先卸掉（与 Docker 冲突，Lance/SP3 均常见）
yum remove -y podman docker-runc 2>/dev/null || true
```

### 2.2 离线安装 Docker Engine + Compose（推荐 · 已核对下载包）

**先在服务器确认架构：**

```bash
uname -m
# 必须是 x86_64。若是 aarch64，不能用下面这两个包，需改下 linux-aarch64 版本。
```

**现场已下载、可用的两个文件（x86_64）：**

| 文件 | 用途 | 是否正确 |
|------|------|----------|
| **`docker-24.0.9.tgz`** | Docker 引擎静态包 | 正确 |
| **`docker-compose-linux-x86_64`** | Compose（Assets 里选的 linux 包） | 正确 |

> 不要用带 `darwin`（Mac）、`windows` 的包；不要下 `.sha256` / Source code。

来源备忘：

- Docker：`https://mirrors.aliyun.com/docker-ce/linux/static/stable/x86_64/docker-24.0.9.tgz`
- Compose：GitHub `docker/compose` Releases → **Show all assets** → `docker-compose-linux-x86_64`（Latest 如 v5.x 即可，不必找旧版号 2.x）

**① 把两个文件上传到服务器**，例如 `/opt/docker-install/`：

```text
/opt/docker-install/docker-24.0.9.tgz
/opt/docker-install/docker-compose-linux-x86_64
```

**② 安装 Docker Engine：**

```bash
cd /opt/docker-install
tar -xzf docker-24.0.9.tgz
cp docker/* /usr/bin/
chmod +x /usr/bin/docker /usr/bin/dockerd /usr/bin/containerd /usr/bin/runc \
  /usr/bin/ctr /usr/bin/docker-proxy /usr/bin/containerd-shim-runc-v2 2>/dev/null || true

cat >/usr/lib/systemd/system/docker.service <<'EOF'
[Unit]
Description=Docker Application Container Engine
Documentation=https://docs.docker.com
After=network-online.target firewalld.service
Wants=network-online.target

[Service]
Type=notify
ExecStart=/usr/bin/dockerd
ExecReload=/bin/kill -s HUP $MAINPID
LimitNOFILE=infinity
LimitNPROC=infinity
TimeoutStartSec=0
Delegate=yes
KillMode=process
Restart=on-failure
StartLimitBurst=3
StartLimitInterval=60s

[Install]
WantedBy=multi-user.target
EOF

mkdir -p /etc/docker
cat >/etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://docker.m.daocloud.io"],
  "log-driver": "json-file",
  "log-opts": { "max-size": "100m", "max-file": "3" },
  "data-root": "/var/lib/docker"
}
EOF
# 若数据盘很大：改 data-root 为 /data/docker，并先 mkdir -p /data/docker

systemctl daemon-reload
systemctl enable --now docker
docker version
```

**③ 安装 Compose：**

```bash
cd /opt/docker-install
mkdir -p /usr/local/lib/docker/cli-plugins
cp docker-compose-linux-x86_64 /usr/local/lib/docker/cli-plugins/docker-compose
chmod +x /usr/local/lib/docker/cli-plugins/docker-compose
ln -sf /usr/local/lib/docker/cli-plugins/docker-compose /usr/local/bin/docker-compose

docker compose version
# 或
docker-compose version
```

**.51 与 .55 两台都按上面装一遍。**
### 2.3 有外网时可试在线安装（备选）

麒麟对 Docker 官方源兼容性差，常失败；成功案例多为 **CentOS 8(el8) 兼容包 + 固定版本**。若失败请改回 §2.2 离线。

```bash
yum remove -y podman docker-runc 2>/dev/null || true
dnf install -y dnf-plugins-core
# 具体 repo/版本以现场镜像站为准，不在此写死易失效的命令长链
```

### 2.4 验证（两台都要过）

```bash
docker run --rm hello-world
docker compose version
```

## 三、代码目录、防火墙（服务器常连不上 Git）

### 3.1 代码怎么放到服务器（推荐：离线打包，不依赖 git clone）

政务云 **经常访问不了 GitHub / 外网 Git**。这时 **不要死磕 `git clone`**，在能上网的电脑上打好包，再拷进内网。

#### 方式 A：本机一键打包脚本（推荐）

在办公电脑（已 clone 本仓库）执行，**只需输入分支名**：

```powershell
cd D:\codeHouse\changhe\smartCityCode\chengde-smart-city

# 先把要上线的改动 commit（脚本只打已提交内容）
git status
git add ...
git commit -m "..."

# 打包（默认输出到桌面）
powershell -ExecutionPolicy Bypass -File .\scripts\pack_prod_release.ps1 -Branch feature_yxj

# 指定输出目录 / 先尝试 fetch
powershell -ExecutionPolicy Bypass -File .\scripts\pack_prod_release.ps1 -Branch main -OutDir D:\release -Fetch
```

Linux/mac：

```bash
./scripts/pack_prod_release.sh feature_yxj ~/Desktop
```

生成文件名类似：`chengde-smart-city_feature_yxj_abc1234_20260730-1130.tar.gz`

传到服务器后：

```bash
sudo mkdir -p /opt/chengde && sudo chown "$USER":"$USER" /opt/chengde
# 上传 tar.gz 到 /opt/chengde/
cd /opt/chengde
tar -xzf chengde-smart-city_*.tar.gz
ls chengde-smart-city/compose
```

**.51 和 .55 都解压一份**（或只在一台解压再 scp 目录到另一台）。

> 脚本用 `git archive`，**未 commit 的文件不会进包**。Docker/Compose 相关改动请先提交再打包。

#### 方式 A2：手工压缩（脚本不可用时）

拷贝仓库目录，删除 `node_modules`、`platform-backend/target`、`local.env`、`compose/prod-*.env` 后打 zip/tar，再上传解压到 `/opt/chengde/chengde-smart-city`。

#### 方式 B：内网有 GitLab / 镜像仓

把代码推到 **内网 Git**，服务器再：

```bash
git clone <内网仓库地址> /opt/chengde/chengde-smart-city
```

#### 方式 C：外网 Git 偶发能通

```bash
sudo mkdir -p /opt/chengde && sudo chown "$USER":"$USER" /opt/chengde
cd /opt/chengde
git clone <仓库地址> chengde-smart-city
cd chengde-smart-city && git checkout <发布分支或 tag>
```

连不上就立刻改回 **方式 A**，不要卡在 clone。

### 3.1.1 本机一键打生产镜像（推荐，双击 bat）

在已装 **Docker Desktop** 的办公电脑上，双击：

`scripts/build_prod_images.bat`

按提示输入分支名（可选改输出目录，默认桌面）。脚本会：

1. 按该分支检出（临时 worktree，不改你当前工作区）
2. `docker build` 前后端，标签含 `smart-city/platform-*:local`（与 `prod-app.yml` 一致）
3. `docker save` 导出到桌面：`chengde-app-images_<分支>_<sha>_<时间>.tar`
4. **自动生成/复用** `prod-mid.env` + `prod-app.env`（随机强密码、两机一致），一并放到输出目录；本机另有 `compose/prod-secrets.local.txt` 口令备忘

> **Git 约定**：`prod-*.env` / `prod-secrets.local.txt` **首次入库要提交**；首次 commit 成功后执行 `scripts/skip_prod_env_after_commit.ps1`，之后本地改密不再进提交。

拷到现场后：

```bash
# .55
docker load -i chengde-app-images_*.tar
# 将输出目录的 prod-app.env 放到仓库 compose/（若用 pack 发包则解压后已自带）

# .51
# 将 prod-mid.env 放到仓库 compose/
```

> 只导出应用镜像。MySQL/Redis 等中间件镜像仍按下面离线 load；现场若在 .55 上 `--build`，还需基础镜像（maven/node/nginx 等）。

### 3.1.2 中间件 / 基础镜像也常拉不下来（提前离线 load）

**.55** 若现场构建还需要基础镜像，**.51** 需要 MySQL/Redis 等。若 `docker pull` 失败，在能上网的机器上 `docker pull` + `docker save`，把 `.tar` 拷进服务器再：

```bash
docker load -i mysql-8.0.tar
docker load -i redis-7-alpine.tar
# 以及 eclipse-temurin、maven、node、nginx 等（.55 现场 build 用；若已用 3.1.1 打好应用包可省略）
```

（具体镜像名见 `compose/prod-mid.yml` / 前后端 Dockerfile。）

## 四、.51：用 Docker「安装」MySQL、Redis、其它中间件

### 4.1 会自动新建的库

| 库名 | 说明 |
|------|------|
| `smart_city` | 业务主库（后端 Flyway 建表） |
| `smart_city_ods` / `dwd` / `dws` / `ads` | 分层仓 |
| `openmetadata_db` / `dataease` / `dolphinscheduler` | 开全 profile 时组件库 |

业务用户：`smart_city`（密码你在 env 里定），允许远程连接。

### 4.2 配置并启动

若本机已用 `gen_prod_env.ps1` / `build_prod_images.bat` / `pack_prod_release.ps1` 打好包，**解压后已有** `compose/prod-mid.env`，可跳过复制与改密，直接启动。

否则手工：

```bash
cd /opt/chengde/chengde-smart-city
cp compose/prod-mid.env.example compose/prod-mid.env
vi compose/prod-mid.env
# 必填：MYSQL_ROOT_PASSWORD、MYSQL_PASSWORD、REDIS_PASSWORD、KETTLE_PASSWORD
```

```bash
chmod +x scripts/prod_up_mid.sh
# 先只起 MySQL + Redis（验证通再开全栈）
./scripts/prod_up_mid.sh

docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
# 应看到 sc_mid_mysql、sc_mid_redis；宿主 MySQL 端口默认 13306
```

**全中间件（ES/OM/DE/DS/Kettle/Canal…，吃内存）：**

```bash
./scripts/prod_up_mid.sh --all
```

等价手写：

```bash
docker compose -f compose/prod-mid.yml --env-file compose/prod-mid.env \
  --profile storage --profile governance --profile bi --profile sched --profile etl --profile cdc \
  up -d
```

### 4.3 自检 MySQL / Redis（在 .51 或从 .55）

```bash
# MySQL（容器内）
docker exec -it sc_mid_mysql mysql -usmart_city -p -e "SHOW DATABASES LIKE 'smart_city%';"

# 从应用机 .55
mysql -h10.10.10.51 -P13306 -usmart_city -p -e "SELECT 1"

# Redis
docker exec -it sc_mid_redis redis-cli -a '你的REDIS密码' ping
# 或从 .55：
redis-cli -h 10.10.10.51 -a '你的REDIS密码' ping
```

没有 `mysql`/`redis-cli` 客户端时，只用 `docker exec` 即可。

## 八、常见问题

| 现象 | 处理 |
|------|------|
| `dockerd` 起不来，提到 podman | `yum remove -y podman` 后重启 docker |
| 拉镜像失败 | 配 `daemon.json` 镜像加速，或离线 `docker load` |
| `.55` 连不上 MySQL | 查 .51 防火墙、`MYSQL_PUBLISH_PORT=13306`、账号密码、`bind-address` |
| Compose 命令找不到 | 按 §2.2 装 cli-plugins；脚本已兼容 `docker compose` / `docker-compose` |
| 内存不够 | .51 先只跑 `prod_up_mid.sh`（无 `--all`），中间件分批加 profile |
